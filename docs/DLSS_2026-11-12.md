# DX12 DLSS Super Resolution — November 12, 2026

Use **Performance > NVIDIA DLSS (experimental)** to choose Off, Quality, Balanced, Performance or DLAA. Off is the default. The astronomy/model scene uses the render size returned by NVIDIA's SDK; DLAA retains display resolution. The native Quantum view remains unchanged.

## Implementation and reasons

| Files | Change and reason |
| --- | --- |
| `src/dx12/Dx12Dlss.h/.cpp` | Real NGX D3D12 initialization, custom-engine GUID, adapter/driver capability query, optimal-size query, feature creation, evaluation, release and shutdown. No borrowed NVIDIA application ID, frame interpolation or renamed spatial filter. Missing DLLs/unsupported hardware leave native rendering available. |
| `src/dx12/Dx12SceneBridge.h/.cpp` | Own fenced HDR reconstruction/motion resources, explicit shader-resource/UAV barriers and output copy. Recreate the NGX feature only after retiring old GPU work on resolution or quality changes. Restore graphics bindings after external SDK work. |
| Same bridge: jitter | Apply a 32-sample Halton offset to actual scene projection and inverse ray matrices, including atmospheres and Kerr rays, before rendering. Turn jitter off before camera post-processing. Stationary scenes accumulate, then reuse their reconstructed image without evaluating DLSS continuously. |
| Same bridge: history | Unchanged scenes have exact zero non-jittered velocity. Every scene/camera/time change resets history until complete per-object and bent-ray velocity fields exist. This intentionally sacrifices temporal accumulation during motion instead of allowing stale planet/cockpit/star images to trail. This is an experimental integration, not production temporal-motion parity. |
| `src/CameraOptics.h/.cpp` | Reconstruct linear HDR before metering, lens flare and display tone mapping. DLSS's internal exposure normalization does not drive the simulation camera's automatic exposure. Lens flare and UI remain downstream. A separate nearest-sample copy preserves the original optical-eligibility alpha; DLSS output alpha never decides whether stellar plasma can seed glare. |
| `src/WindowManager.cpp` | Add quality controls, ask the SDK for the render extent, invalidate scene caching while accumulating, and retain the existing native path when unavailable. SDK resolution overrides the separate black-hole resolution percentage while active. |
| `Render-Engine.DX12.vcxproj`, `tools/BuildShaderTools.cmd` | Build against the official pinned SDK; link matching Debug/Release NGX libraries and deploy the redistributable `nvngx_dlss.dll` with its licence. Source/binary dependencies live in sibling `External_Lib`, not in Git. `EnableDLSS=false` builds the stub fallback. |
| `src/RenderChecks.cpp` | Exercise real Quality/Balanced/Performance/DLAA evaluations, convergence reuse, camera and playback resets, odd resize and return to native rendering. Count evaluations and resets so a displayed menu cannot masquerade as working DLSS. |
| `src/dx12/Dx12Renderer.h`, bridge includes | Isolate Windows SDK types from public scene headers and define NOMINMAX before Windows headers. Avoids macro and C++ byte-name collisions in the shared application. |

SDK source: [NVIDIA/DLSS](https://github.com/NVIDIA/DLSS), revision `9981c6350dc58c0ce21f024fd65e31e851c31689`. Follow [NVIDIA's programming guide](https://github.com/NVIDIA/DLSS/blob/main/doc/DLSS_Programming_Guide_Release.pdf) and the [included licence](../third_party/licenses/NVIDIA-DLSS.txt) for SDK use and redistribution. This project does not publish the SDK sources or DLL in Git.

## Validation and limits

Actual NGX evaluation passed on the NVIDIA GeForce RTX 4080 Laptop GPU. A full Debug suite recorded 40 evaluations and 9 resets, all four reconstruction modes, odd-size resource recreation, and zero DX12 validation errors. The full Debug suite passed 113 scene captures and six UI captures. Controlled optical masks preserved 6,724 excluded pixels with zero errors: excluded emission produced zero optical sources; eligible emission still produced four.

DLSS Super Resolution is not Frame Generation or Ray Reconstruction. Neither of those is integrated. Dynamic scenes currently use reset-per-change reconstruction; a stable paused view receives temporal accumulation. Depth near strongly lensed or blended objects retains the scene's approximate guide, so this mode remains experimental. It does not repair low ray-step integration artifacts, guarantee higher FPS, or establish lower temperatures. Compare against native 100% rendering for a fair performance measurement: the default legacy Kerr pass already uses 50% dimensions.
