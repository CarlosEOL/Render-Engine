# Laboratory menu, physical solar system, and quantum examples

This records the changes and why they were made. The app starts paused at the laboratory menu. F10 always returns there and pauses the active experiment.

## Physical and visual limits

The solar-system **1:1** label means body radii and distances share the same length scale. The eight planetary orbits use JPL's J2000 elements held fixed and Keplerian motion; Earth uses the Earth-Moon barycenter elements as an approximation. No secular element rates, mutual perturbations, current-date ephemeris, lunar barycentric correction or precession is integrated. Moons use approximate two-body geometry with illustrative initial phases/orientations. Named small-body orbits are representative; the Halley model does not predict its present position. Solar surfaces, atmospheres and gas bands are procedural illustrations, not maps or composition-specific atmospheric models. The Sun and all bodies use spherical mean radii. Rings, every known moon, every asteroid, detailed comet tails and an Oort-cloud model are not included.

Gargantua retains the existing scaled Newtonian orbital system and Schwarzschild light renderer. It is not a calibrated Kerr model and cannot reproduce the film's extreme Miller time ratio. Returning through the menu starts the Gargantua experiment from time zero. Solar and generated systems support much larger playback rates than the force-integrated craft demonstration.

Quantum states use nonrelativistic idealized models and dimensionless/atomic units. Hydrogen images are **central slices**, not 3D projections or normalized 2D distributions. Their brightness scales to the current orbital's peak. The one-dimensional chart shares a per-frame peak scale; probability and position statistics are integrated independently from that display scale. Free packets can leave the displayed interval. Numerical experiments have reflecting boundaries at +/-12, finite grid dispersion and finite time-step error. Bell views show Z-basis joint probabilities; they do not implement a quantum computer, measurement shots or interactions with an environment.

The GPU draws wavefunction charts and photographic postprocessing. The small 1D implicit quantum solve, analytic wavefunction sampling, orbital queries, UI and navigation run on the CPU. The black-hole light integrator, terrain, rasterization, atmosphere and lens effects run on the GPU. This is not a claim that every calculation is GPU-resident.

## Reproducible validation

Build Debug x64 with Visual Studio 2022, then run `tests\RunSimulationChecks.cmd` from the project folder. It compiles a CPU-only test executable with the newest installed Visual Studio C++ toolchain, found with vswhere. It checks integrated normalization at several times, qubit probability sums, numerical norm conservation, nonzero barrier reflection/transmission, Earth radius/year and orbit closure, Moon-Earth distance, body counts and deterministic generated systems. Rendering still requires a GPU supporting OpenGL 3.3.

The preview build is `build/menu-preview/bin/Render-Engine.exe`. Startup and scene navigation are also checked in the native app, because a successful C++ build alone does not validate GLSL shaders or native-control layout.
