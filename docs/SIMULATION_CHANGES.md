This records the changes and why they were made. The app starts paused at the laboratory menu. F10 always returns there and pauses the active experiment.

## Physical and visual limits

The solar-system **1:1** label means body radii and distances share the same length scale. The eight planetary orbits use JPL's J2000 elements held fixed and Keplerian motion; Earth uses the Earth-Moon barycenter elements as an approximation. No secular element rates, mutual perturbations, current-date ephemeris, lunar barycentric correction or precession is integrated. Moons use approximate two-body geometry with illustrative initial phases/orientations. Named small-body orbits are representative; the Halley model does not predict its present position. Solar surfaces, atmospheres and gas bands are procedural illustrations, not maps or composition-specific atmospheric models. The Sun and all bodies use spherical mean radii. Rings, every known moon, every asteroid, detailed comet tails and an Oort-cloud model are not included.

Gargantua now uses AU/seconds, a mass of 100 million Suns and an Earth-radius Miller analogue. Its 6.12 AU orbit is 3.1 Schwarzschild horizon radii, outside the non-spinning ISCO. The film places Miller much closer to a nearly extremal Kerr horizon; that orbit and the extreme film time ratio are not reproduced by this model. Returning through the menu starts Gargantua from time zero. Solar and generated systems support larger playback rates than the force-integrated craft demonstration. The Hubble-sized observer envelope is a navigation clearance, not a rendered observatory model or a measured Hubble optical simulation.

Quantum states use nonrelativistic idealized models and dimensionless/atomic units. Hydrogen clouds sample the 3D orbital probability, with a radial probability graph below. Ordinary 1D examples use a Gaussian transverse display thickness; this does not change their governing 1D equation. Dots are statistical probability samples, not tracked classical particles. The one-dimensional chart shares a per-frame peak scale; probability and position statistics are integrated independently from that display scale. Free packets can leave the displayed interval. Numerical experiments have reflecting boundaries at +/-12, finite grid dispersion and finite time-step error. Bell views show Z-basis joint probabilities; they do not implement a quantum computer, measurement shots or interactions with an environment.

The GPU draws wavefunction charts and photographic postprocessing. The small 1D implicit quantum solve, analytic wavefunction sampling, orbital queries, UI and navigation run on the CPU. The black-hole light integrator, terrain, rasterization, atmosphere and lens effects run on the GPU. This is not a claim that every calculation is GPU-resident.

## Reproducible validation

Build Debug x64 with Visual Studio 2022, then run `tests\RunSimulationChecks.cmd` from the project folder. It compiles a CPU-only test executable using the installed Community C++ toolchain. It checks integrated normalization at several times, qubit probability sums, numerical norm conservation, nonzero barrier reflection/transmission, Earth radius/year and orbit closure, Moon-Earth distance, body counts and deterministic generated systems. Rendering still requires a GPU supporting OpenGL 3.3.

The latest preview build is `build/physical/bin/Render-Engine.exe`. Run it with `--render-check build/physical/render-checks` for hidden-window GPU smoke checks and lossless PPM captures. `tests/convert_render_checks.py` converts these to PNG with Python's standard library. Startup and scene navigation were also inspected in the native app; C++ compilation alone does not validate GLSL or control layout.

## Camera rotation and 3D quantum workspace follow-up

- **`CameraMotion.h/.cpp`:** Added shared local-axis look, roll and rigid-frame carry equations. Mouse-look now preserves existing roll and carried object orientation; it no longer reconstructs a world-up Euler direction every frame. Roll uses real elapsed seconds, so Q/E behaves consistently while simulation playback is paused. Surface look retains the gravity-up constraint.
- **`WindowManager.h/.cpp`:** Q/E roll, R/F translate vertically, T toggles position-only follow, and Shift+R toggles position-and-rotation follow. Ctrl+R replaces the conflicting experiment/craft reset binding. Modifier chords suppress upward movement, so toggling follow does not also translate the camera. The other agents' wheel-speed, Shift+RMB zoom, middle-button reset, overlay and native focus changes are retained.
- **`StarSystem.h/.cpp`, `SolarSystem.cpp`:** Added double-precision target rotation and rotational following. Camera offset and both view axes receive the same rotation delta as the selected object, then receive its orbital translation. The star has a nominal 25.38-day spin; planets/moons use their stored spin and tilt. Following is reanchored when enabled and cleared on view/selection changes. This prevents jumps from an old cached frame and remains stationary when playback is paused.
- **`BlackHole.h/.cpp`:** Added rotation queries matching displayed planet and craft orientation, with a nominal spin for ordinary star spheres. The central Schwarzschild black hole returns identity rotation because this model has no intrinsic spin. Rotation-follow uses current physical spacecraft state, while the visible delayed image can show an earlier state.
- **`QuantumParticleView.h/.cpp`:** Added a navigable 3D viewport with GPU point rendering, phase colors, reference axes and a 3D Bloch representation. Hydrogen uses deterministic Metropolis sampling of the analytic three-dimensional Born density; the samples have no physical trajectory identity. 1D states sample their X probability and add explicitly illustrative Gaussian Y/Z thickness. Bell clouds show joint-basis probabilities as a state-space diagram, not two physical particle positions.
- **`QuantumStates.h/.cpp`:** Added full 3D hydrogen functions and normalized radial amplitudes for the graph. Real d-orbital angular factors include all three coordinates, rather than extending a flat slice into depth.
- **`QuantumSimulation.h/.cpp`:** The top 80% is the 3D workspace and the bottom 20% is a compact graph. Hydrogen graphs show radial probability from the normalized radial amplitude; other states retain density/amplitude curves or probability bars. The graph's viewport and projection are independent of the free camera. Home reframes the selected state, and entering a new state starts with a useful camera distance.
- **`WindowManager.cpp`:** Quantum mode now supports the same mouse-look, roll, WASD, R/F and adjustable-speed flight. It preserves the other agents' lens zoom gesture, while scientific graphs stay outside photographic processing.
- **`tests/SimulationChecks.cpp`:** Added radial and angular hydrogen normalization checks, repeated look/roll basis checks, a quarter-day object-rotation carry check and a paused-follow check. The test runner and project register the new shared camera and quantum-view files.
- **`README.md` and this log:** Updated bindings and view descriptions so old F-follow/R-reset instructions do not conflict with the requested flight controls.

## Performance changes and their tradeoffs

- **`OrbitalMechanics.cpp`:** Replaced unconditional 40-step bisection with a bracketed Newton solve, retaining bisection fallback and a finite iteration bound. Typical low-eccentricity solves converge in a few iterations; high-eccentricity tests cover the guarded path.
- **`StarSystem.h/.cpp`, `SolarSystem.cpp`:** Cache all current body positions for a given simulation time and precompute orbit curves once per generated system. Representative belt positions refresh only when the sample age reaches 300 simulated seconds; this is a visual population approximation. The photon diagnostic reuses that cache. Generating/loading a system invalidates caches. Paused time does not solve the same trajectories again.
- **`StarSystem.cpp`, `Atmosphere.cpp`:** Skip unresolved body meshes and sub-pixel/off-screen atmospheres. Small-body markers remain available for navigation. Only the active system is rendered; other systems have no continuously integrated planetary state. Analytic positions catch up to the selected simulation time when a system is visited.
- **`BlackHole.h/.cpp`:** Cache black-hole orbital guide curves and the distant sky cube instead of regenerating them per frame. Catalogue star positions/properties are uploaded once; only the small set of orbiting bodies changes position.
- **`WindowManager.h/.cpp`, `CameraOptics.h/.cpp`:** Reuse the rendered astronomical scene when paused and camera/view state is unchanged. This skips light tracing, atmosphere passes, geometry submission, scene copies and mip generation; postprocessing and transient UI can still update. Input, view changes and resizing invalidate/reframe the cache. A GPU check compares the cached and original frames byte for byte.
- **`main.cpp`, `WindowManager.h/.cpp`:** Added sleeping frame pacing and 30/60/120 FPS choices. Default 60 FPS / 75% internal black-hole resolution reduces light-traced pixel count by about 44% versus full resolution. Menu, unfocused and cached idle frames cap at 30 FPS. 50% and 100% internal resolution remain available. Navigation remains in the full display viewport.
- **`WindowManager.cpp`:** A one-click Cooler mode combines 30 FPS with 50% black-hole resolution. Gargantua starts with trajectory guides hidden to keep the image clear; F2 reveals them. Solar-system overview starts with paths visible. A new scene clears cached view state, and quantum rendering clears the astronomical idle flag so it does not inherit an idle-only frame cap.
- **`BlackHole.cpp`:** Ocean-only fragments return before the unused land/noise shading, reducing close-up water cost. Circular star point masks and restrained reference brightness reduce square, overexposed highlights. Catalogue spectra still follow generated temperatures/luminosities. Flare extraction rejects dim diagnostic markers, rather than treating them as emissive stars.
- **`StarSystem.cpp`, `QuantumParticleView.cpp`:** The five orbiting companions now share the same intrinsic temperature/radius metadata when opened as a star system. Free-packet cloud counts decrease with probability remaining in the displayed interval, rather than resampling a vanishing tail as a full cloud. This keeps visual samples consistent with the displayed statistics.
- **`.gitignore`:** Excludes local validation binaries, logs and screenshots from new untracked build directories. Existing tracked build artifacts are untouched.
- **`RenderChecks.cpp`, project, main, tests:** Added optional `--render-check`, a PNG conversion helper, browser-mode routing checks, physical scale/high-eccentricity tests and cached-frame checks. Normal startup does not run these checks. `GLFW_INCLUDE_NONE` prevents GLAD/header ordering conflicts in test translation units.

These are reductions in repeated work and rendering load. CPU/GPU temperatures have not been measured, and results depend on hardware, resolution and selected settings.

Primary scale references: [NASA Hubble design dimensions](https://science.nasa.gov/mission/hubble/observatory/design/) and [Kip Thorne's discussion of Miller/Gargantua](https://www.its.caltech.edu/~kip/index.html/PubScans/VI-59.pdf). The physical scale is based on the chosen mass; unmodeled Kerr dynamics remain explicitly separate from the film-inspired appearance.

Validation completed: Debug x64 builds; all 38 quantum presets pass normalization/probability checks applicable to their family; the finite-barrier experiment produces both reflection and transmission with conserved discrete norm; physical-scale, moon hierarchy, high-eccentricity solver, deterministic generation, camera-basis and rotational-follow checks pass. Ten GPU render cases report no OpenGL errors, including current/all-system browser routing and byte-identical cached/full black-hole frames. Captured PNGs were visually reviewed for the 3D/graph split, planetary scale, ocean normals, black-hole composition and lens glare. Hardware temperature and full Kerr accuracy are outside those checks.
