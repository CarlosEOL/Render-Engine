Apparent slowing/redshift near a horizon must not be confused with freezing every flyby, or with an infaller seeing an infinite external future; see [NASA's explanation](https://science.nasa.gov/apod/frequently-asked-questions-faqs-on-black-holes/).

## GPU black-hole spin

| Files | Changes | Reason |
| --- | --- | --- |
| `src/KerrSpacetime.cpp/.h` (new) | Added Cartesian Kerr-Schild metric helpers, past-directed null-ray initialization in an orthonormal Eulerian frame, analytic Hamiltonian derivatives, horizon/ISCO radii, a double CPU reference integrator and matching GLSL. | Frame dragging requires a spinning spacetime, not a rotating disk texture. Cartesian coordinates avoid polar-coordinate singularities. CPU integration here is validation only. |
| `src/BlackHole.cpp/.h` | Added bounded GPU RK4 Kerr propagation, signed conserved time momentum and axial angular momentum, spin-dependent capture/ISCO and circular-emitter frequency shifts. Spin zero retains the existing Schwarzschild tracer. Default spin is 0.8. | Make spin affect light paths and disk appearance on GPU. The finite step budget and screen-space treatment of finite objects remain rendering approximations. |
| `src/WindowManager.cpp/.h` | Added spin 0/0.5/0.8/0.98 and 96/160/256-step settings. Defaults are 30 FPS, 50% black-hole scene resolution and a 160-step budget; paused scenes still reuse cached images. | Bound the added GPU workload. No hardware-temperature or fixed FPS improvement is claimed without measurement. |

**Model boundary:** Kerr currently applies to GPU light propagation. Endurance/Ranger force integration and the central camera-clock model remain the validated Schwarzschild approximation, with additional weak planetary potentials. This is not a self-consistent Kerr vehicle simulation. DLSS, Ray Reconstruction, temporal accumulation and generated frames are not implemented. Current low-resolution output uses the existing spatial scaling. See [GRay2's Cartesian Kerr-Schild approach](https://arxiv.org/abs/1706.07062) and the [Interstellar renderer paper](https://authors.library.caltech.edu/records/njdcq-95891) for the physical background, not as a claim that this engine reproduces their production accuracy.
